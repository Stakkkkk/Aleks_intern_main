# Решения Алексея

В этой папке хранятся сдаваемые решения практических задач. Каждая задача имеет собственный каталог.

## Структура каталога задачи

```text
task-NN-name/
├── submission.md
├── configuration/
└── external-processing/
```

- `submission.md` — алгоритм, выбранные коллекции, тесты и вопросы по задаче. Его нужно создать из `submission-template.md`.
- `configuration/` — файловая выгрузка учебной конфигурации, если задача решалась в конфигурации.
- `external-processing/` — файловая выгрузка внешней обработки, если задача решалась во внешней обработке.

Для одной задачи заполняется только один из двух каталогов с исходниками. Второй остается пустым.

Нужна именно **файловая выгрузка исходников**, пригодная для просмотра изменений в Git. Одного бинарного файла `.cf`, `.epf` или `.erf` недостаточно.

Для первого блока алгоритмических задач допустим общий рабочий вариант: одна внешняя обработка, в которой каждая задача запускается отдельной кнопкой. При сдаче конкретной задачи актуальную файловую выгрузку этой обработки все равно нужно положить в `external-processing/` каталога соответствующей задачи, а в `submission.md` указать кнопку или процедуру, где находится решение.

## Порядок сдачи

1. Выполнить задачу и проверить ее на заявленных тестах.
2. Открыть каталог нужной задачи.
3. Скопировать `submission-template.md` в каталог задачи под именем `submission.md` и заполнить его.
4. Выгрузить исходники в `configuration/` либо в `external-processing/`.
5. Выполнить `git status` и убедиться, что в изменениях находятся только файлы своей задачи.
6. Зафиксировать и отправить изменения по согласованной с наставником схеме работы через Git.

Не складывать выгрузку одной задачи в каталог другой и не создавать общую папку в обход каталогов задач. Даже если внешняя обработка одна общая, приемка остается разложенной по задачам.
