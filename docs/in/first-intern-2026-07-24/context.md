# Контекст стажёра

Идентификатор: `first-intern-2026-07-24`.

Дата старта: 2026-07-24.

Статус: до первичной диагностики.

## Известные вводные

- Стажёр приходит с базовым опытом в 1С.
- Он уже понимает простые вещи по метаданным.
- Уровень понимания считается примитивным до проверки на практической задаче.
- Стажёр понимает агентскую работу.
- Наставник хочет использовать fast-track к `1С:Профессионал` через практическое решение.
- Возможная основа практики — дипломная работа стажёра.

## Цели стартового периода

- Быстро проверить реальный уровень стажёра.
- Выбрать сквозное решение или бизнес-сценарий для практики.
- Связать подготовку к `1С:Профессионал` с практическими механизмами платформы.
- Отработать алгоритмическое мышление: последовательности, условия, проверки, движения данных.
- Проверить, как стажёр использует агента и не подменяет ли агентом собственное понимание.

## Принятые решения

- В рабочих файлах пока не фиксировать персональные данные.
- Для стажёра использовать идентификатор `first-intern-2026-07-24`.
- Стартовая диагностика должна идти через объяснение бизнес-процесса, карту метаданных и маленькую практическую задачу.
- `1С:Профессионал` готовить через связку "вопрос -> механизм -> практическая проверка".

## Допущения

- У стажёра может быть дипломная работа, подходящая как лаборатория.
- Если дипломная работа слишком широкая или слабая, нужно выбрать один учебный торговый сценарий и расширить его интеграциями.
- При хорошем темпе стажёр может раньше базового графика перейти к проектоподобным задачам уровня L1-L2.

## Открытые вопросы

- Как зовут стажёра и нужно ли фиксировать имя в рабочих документах.
- Какой у него фактический уровень по запросам, регистрам, проведению, формам, интеграциям, правам и администрированию.
- Есть ли у него готовая дипломная конфигурация или только описание.
- Подходит ли дипломная работа как сквозное решение.
- Какая целевая дата сдачи `1С:Профессионал`.
- Где будет храниться код или выгрузка учебной конфигурации.
