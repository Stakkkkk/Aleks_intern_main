# План на 2026-08-04 — 2026-08-21

Дата: 2026-08-03.

Статус на 2026-08-24: календарная итерация завершена. Экзамен `1С:Профессионал` назначен на 2026-08-25;
незакрытые результаты этой итерации переходят во входные ворота следующего этапа.

Следующий этап: [реальная практика и подготовка к 1С:Специалист](alexey-practical-and-specialist-plan.md).

Первичная разработка закончена. Дальше идем в три параллельных направления:

1. подготовка к `1С:Профессионал`;
2. запросы и практика на демо УНФ;
3. прикладные механизмы: печатные формы, Excel, события, первые подключения БСП.

## Главные правила

- Каждый день по `1С:Профессионал`: 3 подхода по 1 часу с перерывами.
- Пока не завершен первый просмотр всех 900 вопросов, используй каждый подход для новых вопросов. Читай
  объяснения, но не застревай на одной теме ради процента правильных ответов.
- На первом проходе достаточно коротко помечать непонятную тему. Полный журнал ошибок, повторение слабых тем и
  смешанные контрольные наборы начинаются после просмотра всех вопросов.
- По запросам и механизмам не ограничивайся чтением: каждый блок должен заканчиваться маленькой практической проверкой в 1С.
- Если застрял на одном месте больше 10–15 минут, фиксируй вопрос и пиши наставнику.
- Все запросы из практики веди в одном списке консоли и сдавай одним сохраненным файлом в
  `docs/in/alexey-solutions/query-practice/`.
- В любой прикладной задаче верхнеуровневый метод строй как последовательность `подготовить данные → обработать →
  записать, вывести, напечатать или вернуть результат`. По именам вызываемых методов должен читаться общий ход
  решения.
- Связанные данные передавай осмысленной структурой или таблицей, если перечень отдельных параметров начинает
  разрастаться. Не дроби код до универсальных методов, из названий которых исчезает предметный смысл.

### Проф

До завершения первого прохода каждый день:

1. Первый час — новый блок еще не просмотренных вопросов.
2. Второй час — продолжение новых вопросов после перерыва.
3. Третий час — еще один блок новых вопросов после перерыва.

После ответа прочитай объяснение. Если тема непонятна, коротко пометь ее и при необходимости найди объект в
конфигураторе, но не превращай первый проход в заучивание одного раздела. Текущий процент правильных ответов на
этом этапе не является целевой метрикой.

После просмотра всех 900 вопросов режим меняется:

1. один подход — разбор слабой темы и правила по ошибкам;
2. один подход — новый тематический набор по этой теме;
3. один подход — смешанный контрольный набор без подсказок.

К 2026-08-07 должен быть полный первичный проход вопросов и список слабых тем.

Для навигации по объектам платформы используй [карту метаданных 1С](alexey-metadata-map.md), но определения и
свойства проверяй в конфигураторе и официальной документации.

К четвергу 2026-08-06 ожидается, что ты умеешь:

- открыть консоль запросов;
- собрать запрос конструктором;
- вручную поправить текст запроса;
- поставить параметры;
- сделать отбор, сортировку, группировку, соединение и условие по агрегированному результату через `ИМЕЮЩИЕ`;
- выполнить пакетный запрос, поместить данные во временную таблицу и использовать ее в следующей части пакета;
- объяснить, откуда берутся данные и как проверял результат.

Запускай приложенную внешнюю обработку в режиме `1С:Предприятие`. Каждую задачу добавляй в общий список запросов
под номером из задания. Командой консоли `Сохранить запросы в файл` сохраняй весь список в один файл; расширение,
которое предложит консоль, не меняй. Этот единый файл и является решением по блоку запросов.

На приемке не требуется перечислять все агрегатные функции наизусть. Требуется объяснить метод решения: какие
таблицы и секции запроса выбраны, как проверен результат и можно ли задачу целиком решать запросом или часть
логики должна остаться во встроенном языке.

К приемке 2026-08-07 обязательно выполни первый пакетный запрос с временной таблицей. Многошаговый пакет,
индексацию временной таблицы и повтор задачи «номенклатура без продаж» через временную таблицу закрой не позднее
2026-08-11.

## Неделя до 2026-08-14: практика механизмов + Проф

Цель недели: много практики и рост качества по Профу.

### Фактический статус на 2026-08-12

- По печатным формам изучены внутренний механизм и перенос формы во внешнюю обработку. На приемке нужно показать
  рабочую форму и отдельно разобрать добавление поля подтверждения директора.
- По Excel условие задачи понято, разработка решения начата; ближайшая цель — довести сценарий до рабочего
  результата.
- По Профу просмотрены и изучаются разделы, включая большой раздел по формам. На контрольной точке нужен один
  смешанный прогон без подсказок и список повторяющихся ошибок: количество просмотренных вопросов само по себе не
  подтверждает усвоение.
- События и подписки начинай после завершения печатной формы и Excel. Если до конца недели эти два результата не
  приняты, не открывай третий незавершенный блок.

До 2026-08-11 закончи обязательный блок запросов на многошаговые пакеты, временные таблицы и
`ИНДЕКСИРОВАТЬ ПО`. Он остается частью практики этой недели, а не переносится «на потом».

По Профу ориентир:

- общий результат тренировочных прогонов — 75–80%+;
- по слабым темам не проваливаться ниже 60%;
- ошибки не просто перерешивать, а разбирать.

### Печатные формы

Материал: <https://kb.korusconsulting.ru/pages/viewpage.action?pageId=135561690>

Что сделать:

- найти существующую печатную форму в УНФ;
- понять, где макет и откуда берутся данные;
- сделать простую учебную печатную форму;
- показать наставнику вызов формы и код формирования;
- на верхнем уровне явно разделить получение данных, подготовку печатной формы и вывод результата.

Результат приемки: внешняя печатная форма запускается, получает данные и формирует результат; ты можешь показать,
где меняется макет и как в него передается новое поле.

Дополнение по ревью 2026-08-17: в модуле объекта должен быть реализован метод `Печать`. Проверяется именно вызов
внешней печатной формы из целевой конфигурации; наличие обработки и макета без рабочего вызова не считается
готовым результатом.

### Excel

Материал: <https://kb.korusconsulting.ru/pages/viewpage.action?pageId=135561692>

Что сделать:

- выгрузить табличные данные в Excel или табличный документ;
- если окружение позволяет, сделать простой импорт;
- зафиксировать ограничения, если учебная платформа мешает печати или сохранению файлов;
- разделить чтение/подготовку данных, преобразование и запись или отображение результата по отдельным методам.

Результат приемки: один законченный сценарий работает на контрольном файле, а ты можешь объяснить входные данные,
преобразование, результат и обработку ошибочных условий.

Дополнение по ревью 2026-08-17:

- верхнеуровневый метод читается как `прочитать → подготовить → создать документ`, а инициализация вынесена;
- пустые данные и неподходящие строки закрываются ранним `Возврат` или `Продолжить` без лишней вложенности;
- граница табличного документа определяется через `ВысотаТаблицы`, повторяющееся чтение ячеек вынесено;
- ссылки на номенклатуру, единицы измерения и виды цен получаются одним запросом, а не запросами внутри цикла;
- типы нормализуются на этапе подготовки; создание документа получает уже проверенные данные;
- чтение файла и запись объектов обрабатываются через `Попытка ... Исключение` с понятным сообщением и явным
  завершением;
- `ОписаниеТипов.ПривестиЗначение()` применяется только если значение по умолчанию допустимо по бизнес-смыслу;
  некорректную цену нельзя молча превращать в ноль.
