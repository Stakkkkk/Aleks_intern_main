# Шаблон оценки учебной или рабочей задачи

Заполняй до начала работы и дополняй после приемки. Коротких формулировок достаточно.

## До начала

### Результат

- Что должно работать:
- Для кого и в каком сценарии:
- Что не входит в задачу:

### Критерии готовности

- [ ] основной сценарий;
- [ ] граничные и ошибочные случаи;
- [ ] самостоятельная проверка;
- [ ] выгрузка результата;
- [ ] демонстрация наставнику;
- [ ] замечания ревью закрыты.

### Короткое описание верхнего уровня

Для большого незнакомого механизма сначала пройди типовой образец до конца в отладчике и коротко опиши его крупные
этапы применительно к своей задаче. Это первый материал для обратной связи, еще не подробная оценка.

| Крупный этап | Что получает и какой результат передает дальше | Что предполагается сделать в своей задаче |
|---|---|---|
|  |  | Изменить / использовать типовое / уточнить |

Достаточно нескольких содержательных пунктов. Не переписывай все вложенные методы. Сначала передай это описание
наставнику, получи обратную связь, затем детализируй необходимые изменения.

### Технический план реализации

Раскрой согласованные пункты верхнего уровня до конкретных работ. Отделяй описание существующего механизма от
своих изменений: оцениваются работы, которые предстоит выполнить, а не весь прочитанный код.

| Точка изменения | Событие, метод или запрос | Что изменить или использовать без изменений | Зачем | Как проверить |
|---|---|---|---|---|
| Объект или модуль |  |  |  |  |

- Типовой образец или похожий механизм:
- Что проверено в документации:
- Что просмотрено в отладчике:
- Верхнеуровневая последовательность методов:
- Архитектурные вопросы наставнику:

Формулировки уровня «реализовать механизм» недостаточны: из плана должно быть понятно, в каких точках и зачем
меняется решение. Подробный план и оценку передай наставнику до основной реализации.

### Каркас до содержимого

- [ ] перечислены верхнеуровневые методы;
- [ ] понятен порядок вызовов;
- [ ] созданы методы-пустышки для основных шагов;
- [ ] по именам методов читается общий алгоритм;
- [ ] структура решения проверена до написания внутренних деталей.

### Декомпозиция и оценка

Разбей конкретные изменения из технического плана на оцениваемые работы. Общие этапы ниже — напоминание о составе
работ, а не требование оставить всю реализацию одной строкой.

| Этап | Результат этапа | Оценка | Неизвестное или риск |
|---|---|---:|---|
| Разобрать условие и найти документацию |  |  |  |
| Спроектировать решение |  |  |  |
| Реализовать |  |  |  |
| Подготовить и выполнить проверки |  |  |  |
| Исправить ожидаемые замечания |  |  |  |

- Общий диапазон:
- Наиболее вероятная оценка:
- Уверенность: низкая / средняя / высокая.
- Что может изменить оценку:
- Контрольная сверка с наставником:

Не прячь исследование внутри разработки. Если механизм используется впервые, оцени изучение отдельно.

## Во время работы

- Потрачено к контрольной точке:
- Что уже готово:
- Что осталось:
- Изменились ли вводные:
- Новая оценка и причина изменения:
- Нужен ли вопрос наставнику:

Оценку нужно пересмотреть, если закончилась половина прогнозного времени, а рабочего пути или проверяемого
промежуточного результата еще нет.
