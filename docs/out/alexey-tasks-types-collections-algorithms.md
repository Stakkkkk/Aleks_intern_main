# Практические задачи: типы, коллекции и алгоритмы

Дата: 2026-07-24.

Этот комплект относится к пункту 3 технического маршрута — «Алгоритмы и код». Задачи выполняются последовательно и выдаются наставником сериями.

## Общие ограничения

- Использовать встроенный язык 1С и универсальные коллекции значений.
- Не использовать язык запросов, объекты конфигурации и интерфейсные формы: до них дойдем отдельно.
- Каждую законченную операцию оформлять отдельной процедурой или функцией.
- Не изменять входную коллекцию, если это прямо не разрешено условием.
- Перед кодом написать алгоритм обычными словами.
- После кода подготовить тесты, включая пустой ввод, одно значение и граничные случаи.
- Если условие допускает несколько трактовок, сначала письменно зафиксировать выбранную трактовку.

Для каждой задачи нужно указать, какие разделы синтакс-помощника (`Ctrl+F1`) использовались и почему выбраны именно эти коллекции.

## Куда складывать решения

Для каждой задачи заранее создан отдельный каталог в `docs/in/alexey-solutions/`. Карта каталогов и порядок сдачи находятся в [инструкции по размещению решений](../in/alexey-solutions/README.md).

Порядок работы с каждой задачей:

1. открыть каталог, соответствующий номеру задачи;
2. создать в нем `submission.md` из шаблона `docs/in/alexey-solutions/submission-template.md` и заполнить алгоритм, тесты и пояснения;
3. если задача решалась внутри конфигурации, выполнить файловую выгрузку в подкаталог `configuration/`;
4. если задача решалась как внешняя обработка, выполнить файловую выгрузку в подкаталог `external-processing/`;
5. проверить изменения через `git status` и отправить решение по согласованной схеме работы через Git.

Для одной задачи нужен только один вариант файловой выгрузки. Одного бинарного файла `.cf`, `.epf` или `.erf` недостаточно: в репозитории должны находиться выгруженные исходные файлы, по которым Git сможет показать изменения.

## Серия A. Обязательный минимум

### Задача 1. Паспорт значения

Написать функцию, которая принимает произвольное значение и возвращает структуру со сведениями о нем.

В результате должны быть поля:

- `Тип` — тип переданного значения;
- `ЭтоНеопределено`;
- `ЭтоNull`;
- `Заполнено`;
- `Представление` — строковое представление значения.

Обязательные проверки:

- непустая и пустая строка;
- ноль и ненулевое число;
- дата;
- `Истина` и `Ложь`;
- `Неопределено`;
- `Null`;
- пустой массив.

Критерий приемки: функция работает с каждым тестовым значением без падения, а Алексей может объяснить разницу между типом, заполненностью и строковым представлением.

### Задача 2. Нормализация наименований

На вход подается массив строк. Нужно вернуть новый массив уникальных нормализованных наименований.

Правила:

1. удалить пробелы по краям;
2. несколько пробелов внутри строки заменить одним;
3. пустые строки отбросить;
4. дубли искать без учета регистра;
5. в результат помещать первое встретившееся очищенное написание.

Пример входа:

```text
"  ООО Ромашка  "
"ооо ромашка"
""
"   "
"ИП  Лес"
"ИП Лес"
```

Ожидаемый результат:

```text
"ООО Ромашка"
"ИП Лес"
```

Требование к коллекциям: порядок хранить в массиве, а проверку уникальности организовать через соответствие. Объяснить, почему проверять каждый элемент полным перебором массива хуже.

### Задача 3. Календарь периода

Написать функцию, которая принимает дату начала и дату окончания и возвращает таблицу значений — по одной строке на каждый календарный день включительно.

Колонки результата:

- `Дата`;
- `ДеньНедели`;
- `НачалоНедели`;
- `НачалоМесяца`;
- `Выходной` — суббота или воскресенье.

Правила:

- время во входных датах не должно влиять на результат;
- если начало позже окончания, вернуть понятную ошибку или пустой результат — выбранное поведение зафиксировать до написания кода;
- функция не должна использовать производственный календарь.

Проверки:

- период из одного дня;
- период с пятницы по понедельник;
- переход между месяцами;
- начало позже окончания.

### Задача 4. Частотный словарь

На вход подается массив кодов. Нужно нормализовать коды, посчитать число появлений каждого кода и вернуть таблицу значений.

Колонки результата:

- `Код`;
- `Количество`;
- `ПерваяПозиция` — индекс первого появления во входном массиве;
- `ЭтоДубль`.

Правила нормализации: убрать пробелы по краям, привести к верхнему регистру, пустые значения отбросить.

Пример:

```text
Вход:  [" a-01 ", "A-01", "B-02", "A-01", "", "b-02"]
Итог:  A-01 — 3 раза, первая позиция 0
       B-02 — 2 раза, первая позиция 2
```

Требование к коллекциям: подсчет выполнить через соответствие, итог представить таблицей значений.

## Серия B. Основной уровень

### Задача 5. Свод строк заказа

На вход подается таблица значений с колонками:

- `Номенклатура`;
- `Склад`;
- `Количество`;
- `Цена`.

Нужно вернуть новую таблицу, свернутую по паре `Номенклатура + Склад`.

Колонки результата:

- `Номенклатура`;
- `Склад`;
- `Количество` — сумма количества;
- `Сумма` — сумма произведений `Количество * Цена` по исходным строкам.

Контрольный пример:

| Номенклатура | Склад | Количество | Цена |
|---|---|---:|---:|
| Товар А | Склад 1 | 2 | 100 |
| Товар А | Склад 1 | 3 | 110 |
| Товар А | Склад 2 | 1 | 110 |
| Товар Б | Склад 1 | 4 | 50 |

В результате для `Товар А + Склад 1` должны получиться количество `5` и сумма `530`.

Ограничения:

- входную таблицу не изменять;
- группировку выполнить алгоритмом на коллекциях, без запроса;
- способ представления составного ключа выбрать самостоятельно и объяснить его.

### Задача 6. Полная проверка строк заказа

На вход подается таблица строк заказа и параметр `КонтрольнаяДата`.

Колонки входной таблицы:

- `НомерСтроки`;
- `Номенклатура`;
- `Количество`;
- `Цена`;
- `ДатаОтгрузки`.

Правила проверки:

- номенклатура заполнена;
- количество имеет тип `Число` и больше нуля;
- цена имеет тип `Число` и не меньше нуля;
- дата отгрузки заполнена, имеет тип `Дата` и не раньше контрольной даты.

Нужно вернуть таблицу всех найденных ошибок с колонками:

- `НомерСтроки`;
- `Поле`;
- `КодОшибки`;
- `ТекстОшибки`.

Ключевое требование: не останавливаться на первой ошибке. Одна строка может дать несколько записей результата.

### Задача 7. Топ-N без изменения источника

На вход подается таблица с колонками `Номенклатура` и `Сумма`, а также число `N`.

Нужно вернуть новую таблицу с первыми `N` строками по убыванию суммы.

Правила:

- исходную таблицу не изменять;
- при равной сумме сортировать по представлению номенклатуры по возрастанию;
- если `N` больше числа строк, вернуть все строки;
- если `N <= 0`, вернуть пустую таблицу;
- отдельно проверить пустой источник.

Уровень «плюс»: добавить в результат место строки в рейтинге и письменно определить, получают ли строки с равной суммой одинаковое место.

## Серия C. Самостоятельные алгоритмы

### Задача 8. Пропорциональное распределение суммы

На вход передаются общая сумма и таблица коэффициентов:

- `Получатель`;
- `Коэффициент`.

Нужно добавить в результат колонку `Распределено` и распределить общую сумму пропорционально коэффициентам с точностью до копеек.

Алгоритмические правила:

1. общая сумма не должна быть отрицательной;
2. сумма коэффициентов должна быть больше нуля;
3. отрицательные коэффициенты запрещены;
4. предварительная доля равна `ОбщаяСумма * Коэффициент / СуммаКоэффициентов`;
5. каждую долю округлить до двух знаков;
6. остаток от округления прибавить получателю с наибольшим коэффициентом;
7. при равных максимальных коэффициентах остаток получает первый из них;
8. сумма результата должна в точности равняться исходной сумме.

Контрольный пример:

```text
Общая сумма: 100
Коэффициенты: 1, 2, 3
Результат: 16,67; 33,33; 50,00
```

Обязательные проверки:

- один получатель;
- коэффициенты `1, 1, 1` и сумма `0,01`;
- один нулевой коэффициент;
- все коэффициенты нулевые;
- отрицательный коэффициент;
- отрицательная общая сумма;
- пустая таблица.

В пояснении отдельно ответить, откуда появляется остаток округления.

### Задача 9. Распределение отгрузки по складам

На вход передаются требуемое количество и таблица складов в порядке приоритета:

- `Склад`;
- `Остаток`.

Нужно распределить требуемое количество по складам сверху вниз. Со склада можно взять не больше его остатка.

Результат должен содержать:

- таблицу распределения с колонками `Склад`, `Остаток`, `КОтгрузке`;
- `Недопоставка` — сколько товара не удалось набрать.

Контрольный пример:

```text
Потребность: 120
Склад 1: 50
Склад 2: 30
Склад 3: 100

К отгрузке: 50, 30, 40
Недопоставка: 0
```

Повторить пример с потребностью `250`: недопоставка должна составить `70`.

Обработать нулевую потребность, пустую таблицу, нулевые остатки и отрицательные входные значения.

### Задача 10. Упаковки и грузовые места

На вход подаются количество товара и количество единиц в одной полной упаковке.

Нужно вычислить:

- число полных упаковок;
- остаток товара вне полных упаковок;
- общее число грузовых мест, если любой ненулевой остаток занимает еще одно место.

Примеры:

| Количество | В упаковке | Полных упаковок | Остаток | Грузовых мест |
|---:|---:|---:|---:|---:|
| 100 | 20 | 5 | 0 | 5 |
| 101 | 20 | 5 | 1 | 6 |
| 19 | 20 | 0 | 19 | 1 |
| 0 | 20 | 0 | 0 | 0 |

Нулевой или отрицательный размер упаковки должен обрабатываться как ошибка. Допустимость дробного количества нужно определить до написания кода и обосновать.

## Серия D. Максимум

### Задача 11. Дерево категорий с итогами

На вход подается таблица с колонками `Путь` и `Сумма`. Уровни пути разделены символом `/`.

Пример входа:

```text
Продажи/Онлайн/Сайт             100
Продажи/Онлайн/Маркетплейсы     150
Продажи/Розница                  200
Сервис                            50
```

Нужно построить дерево значений, где каждый элемент пути становится отдельным узлом, а родительские узлы содержат сумму всех вложенных элементов.

Ожидаемые итоги:

```text
Продажи                         450
  Онлайн                        250
    Сайт                        100
    Маркетплейсы                150
  Розница                       200
Сервис                           50
```

Требования:

- одинаковые пути объединять;
- пустые элементы пути не создавать;
- расчет итогов выполнить отдельной рекурсивной функцией;
- исходную таблицу не изменять;
- объяснить, почему для результата выбрано дерево значений.

## Как сдавать одну задачу

Формат сдачи уже подготовлен в `docs/in/alexey-solutions/submission-template.md`. Для каждой задачи его нужно скопировать в каталог задачи под именем `submission.md` и заполнить.

Задача считается законченной, когда заполнен `submission.md`, добавлена файловая выгрузка, код проходит заявленные тесты, а выбор алгоритма и коллекций можно объяснить словами.
